Showing branches who was reminded before the EMI date

Before each EMI date, borrowers get reminders by phone, AI calls, WhatsApp, SMS and field visits. But nobody could see, per loan or per branch, what had actually happened. I designed one view of pre-due outreach for management, and simple calling tools for branch teams.

RolePM: problem framing, prototypes, PRD
UsersManagement, branch managers, branch credit managers
Window26th to 5th, before the EMI date
SurfacesWeb dashboard + field app
5outreach channels in one view
3personas, each with its own screen
1missing workflow step uncovered

Company, branch and people details are anonymised. Figures are rounded.

01 · ProblemLots of outreach, no visibility

The pre-due window is the cheapest time to prevent a missed EMI. Several teams were contacting borrowers, through telecallers, AI calls, WhatsApp, SMS and visits, but each channel reported separately. A branch manager couldn't answer a basic question: which of my borrowers due this month has nobody reached yet?

02 · FramingWhat is this dashboard for?

The first draft was built from an existing collections dashboard and showed everything. I pushed it back to one purpose: help improve collection efficiency. Every widget had to answer "what will someone do differently after seeing this?"

  • Cut extra charts down to one 30-day trend and month-on-month arrows.
  • Added Zone → Region → Area → Branch filters, since that's how managers review performance.
  • Added payment details: auto-debit vs UPI, and first-time auto-debit success vs bounce.

03 · Three personasDifferent screens for different jobs

  • Management: coverage and outcomes by channel and geography.
  • Branch manager (web): an awareness calling tab on each loan, with "needs attention" signals and next actions such as re-call, field visit or log contact.
  • Branch credit manager (field app): a calling list, the next customer, and call history. No campaign setup, because that's not their job.

04 · A useful bugWhen empty data is really a missing step

The "Assigned to" column was empty for most loans, which looked like a data bug. Tracing it back, there was no step that actually assigned loans to callers. I wrote it up as a missing distribution step in the workflow, which changed the fix from a data patch to a product change.

05 · LearningsWhat I'd do again

  • Ask what action a dashboard drives before adding a single chart.
  • Design per persona. One screen for everyone ends up useful to no one.
  • Treat empty fields as questions about the process.
