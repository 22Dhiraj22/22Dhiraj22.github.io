AI Credit Policy Check: audit a loan file in minutes, and explain why

Checking a disbursed loan file against credit policy meant an auditor reading documents, photos and notes line by line. I designed a tool that runs every policy check on a file and explains each result in plain language, so auditors spend their time on the exceptions.

RolePM: design brief, prototype, PRD
UsersCredit audit and risk teams
BuiltJul 2026; reviewed Sep 2026
StackRules + LLM with vision, JSON output
43policy checks across 5 sections
~3 minto audit one file end to end
~$0.05model cost per file

Company, branch and people details are anonymised. Figures are rounded.

01 · ProblemPolicy audits were slow and inconsistent

Each state has its own credit policy, with dozens of rules on eligibility, income, collateral, documents and field verification. After disbursal, auditors checked files against these rules by hand. Two auditors could read the same file differently, and nobody could audit every file.

02 · ApproachRules decide, AI explains

The key decision was where the AI should and shouldn't have the final word. A credit audit has to be repeatable and defensible, so:

Option A: let the LLM judge everythingFast to build, but the same file could get different answers, and the reasoning is hard to defend in an audit.
Option B: rules for the verdict, LLM for reading and explainingObjective checks (ages, ratios, amounts, dates) are plain rules. The model reads documents and photos, pulls out the facts, and writes a short explanation for each check.

The output is structured: a pass, fail or "needs review" per check, grouped into 5 policy sections, with the evidence and explanation alongside. Auditors start from a section drill-down rather than a long report.

03 · What I builtFrom brief to working prototype

  • A design brief mapping every policy rule to a check, the data it needs and who owns the exception.
  • A clickable prototype of the audit summary and the section drill-down.
  • A working checker covering 43 checks for 2 state policies, reading photos as well as data.
  • The PRD and Jira breakdown for bringing it into the loan origination system.

04 · Testing it honestlyFinding where the AI wobbled

When I re-ran identical files a couple of months later, 6 of the 43 checks gave different answers between runs. All of them were checks where the model was making a judgement that a rule could make instead.

The fix I proposed: move every objective check to deterministic code, keep the model only for reading documents and writing explanations, fix the model settings for repeatability, and cache results per file version so a re-run of an unchanged file returns the same answer.

The useful question isn't "can AI do this?" It's "which parts must give the same answer every time?"

05 · LearningsWhat I'd tell another PM

  • Draw the line between judgement and rules early, and write it in the PRD.
  • Re-run the same inputs. Repeatability testing found a problem that single demos never would.
  • Cost per decision matters. At ~$0.05 a file, auditing every file becomes realistic, not just a sample.
