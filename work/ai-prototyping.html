Prototypes that match production UI on the first try

Every AI-generated prototype looked "almost right" and took several rounds of screenshots and corrections. I turned our design system into a reusable UI kit the AI uses by default, so the first draft already looks like the real product.

01 · ContextPrototypes are how we align

Our platform covers origination, loan management, HRMS and collections. Before engineering builds a feature, we need a prototype that stakeholders like branch ops and credit heads can react to. AI tools made prototypes fast to produce, but they didn't look like our product.

02 · Problem"Almost right" is expensive

  • Each prototype took 4–5 rounds of screenshots and corrections to match our colours, tables, forms and spacing.
  • Stakeholders got distracted by visual differences instead of reviewing the workflow.
  • Engineers couldn't tell which parts of the prototype were intentional and which were AI mistakes.

03 · InsightThe AI wasn't missing skill, it was missing context

The design system already existed in Figma. What was missing was a version of it the AI could read and reuse: design tokens, component classes, and a starter template.

04 · SolutionA design system the AI can use

Figma design system

→

→
Template + scaffolder
→
AI skill
  • Tokens: colours, type, spacing and radii pulled from Figma into one CSS file.
  • Components: tables, forms, status chips, sidebars and cards written as reusable classes.
  • Scaffolder: a one-line command creates a new prototype that is already in the company's style.
  • Packaged as an AI skill: the assistant uses it automatically whenever someone asks for a company screen.

05 · ImpactWhat changed

  • Prototypes now need about one review round instead of 4–5.
  • Reviews focus on the workflow and edge cases, not pixels.
  • Prototypes are attached to Jira tickets as clear references for engineering.

06 · LearningsWhat I took away

  • With AI, better context beats better prompts. Investing once in a shared foundation paid off on every prototype after it.
  • Keep the kit in sync. When the design system changes, the kit has to change too. Next step: make that sync automatic.
